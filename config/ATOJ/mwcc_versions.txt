# Per-file mwccarm versions.
#
# The whole ROM builds byte-exactly with a single compiler, 1.2/b56 (build 56,
# Runtime Built 2004-09-16, NITRO V1.0), which is what tools/configure.py
# defaults to. The game shipped in Japan on 2004-12-30, so b56 is the only
# vendored build that predates the cartridge: everything from 1.2/sp2 (build 79,
# Runtime Built 2005-08-11) onwards was released months after the ROM was in
# shops, and a post-release build is a prior against a unit, never evidence for
# one. There is no entry left in this file.
#
# The one entry it used to carry was src/arm9/func_0201fcc8.c = 2.0/base, for a
# nine-word Thumb block that 3.0 build 114 reproduced from C and every 1.2 build
# did not: b56 loaded the 0x1000 it stores from a literal pool and appended a
# nop, 4 bytes longer, and 20 source spellings did not move it. That was the
# wrong question. The block is NitroSDK's hand-written `MTX_RotX33_` asm in
# fx_mtx33.c, assembled by mwasmarm and shipped inside the SDK, so no C compiler
# was ever asked to produce it. Written as an `asm void` block in that file's
# own instruction sequence, 1.2/b56 assembles it byte for byte and the digest
# matches with no override at all. The finding is recorded in
# notes/mwccarm-codegen-log.md.
#
# This file remains the escape hatch for a unit that genuinely has evidence of a
# different origin. An entry needs the full ROM digest to still match, and the
# tag must exist under tools/mwccarm/<tag>/mwccarm.exe. Editing this file only
# takes effect after re-running tools/configure.py ATOJ: build.ninja does not
# list it as an input, so an edit alone changes nothing.
#
# Format: <source path> = <version tag>
