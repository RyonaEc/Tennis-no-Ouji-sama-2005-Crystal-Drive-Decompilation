# ov005 `func_ov005_020695bc` - 4x220 family decode, 5 register slots short

Same skeleton as `0x020614a4`, `0x020656d8`, `0x0206bfc0` (4 members, 880 B).
The decode below is the whole function; the transcription
(`build/cand/o5_95bc_f.c`, `_g.c`) is **exactly 220 B with retail's instruction
sequence** and differs only in which of `ip`/`lr` holds two temporaries.

```c
s32 func_ov005_020695bc(s32 a0)
{
    u8 *base = *(u8 **)data_ov005_020c9740;

    if (a0 == 0) {
        func_020209c8(8);
        func_020208b0(0x100);
        *(u32 *)0x04001000 = (*(u32 *)0x04001000 & 0xffcfffef) | 0x00100010;
        for (i = 0; i < 0x200; i++) {
            u8 *p = base + i * 2;

            *(u16 *)(p + 0x4a58) = 0;
            if (i % 4 == 0)
                *(u32 *)(p + 0x4a58) = 0x200;
        }
        if (*(u16 *)(base + 0x4388) < 0x1f4) {
            func_02025c94((u32)(base + 0x4658), 0x400);
            func_02026a50(base + 0x4658, (void *)0x07000000, 0x400);
        }
    }
    return 0;
}
```

`i` is a `u16` (the `lsl #16`/`lsr #16` pair). The guard is **`i % 4 == 0`**,
not `i % 2`: mwcc encodes `i % n` as `lsr #31` + `rsb (i << (32-k))` + `adds …
ror #(32-k)` where k = 1 for `% 2` and k = 2 for `% 4`, so `lsl #30`/`ror #30`
in retail means the mask is 3. Getting this wrong costs one instruction and
keeps the loop body two slots off.

Spelling notes that matter:

- the loop body needs its own `u8 *p = base + i * 2;`; writing
  `base + 0x4a58 + i * 2` inline makes mwcc hoist a pooled `0x4a58` out of the
  loop and the unit grows to 228 B;
- `if (a0 != 0) return 0;` at the top lets b56 predicate the early return;
  wrapping the body in `if (a0 == 0) { … } return 0;` gives retail's `bne` past
  the whole body.

## Residue

| | retail | candidate |
|---|---|---|
| zero constant (the `strh` value) | `ip` | `lr` |
| `p = base + i * 2` | `lr` | `ip` |

Five slots, all of it that pair. Tried: declaration shuffle over 6 orders
(permute, 4,246 candidates, best 5 structural), a named `u16 zero` assigned
before the loop (same 5), and storing the u16 after the guarded u32 store (mwcc
merges the two stores, 212 B). The tie is the one this family's wall note
already names, so do not spend another declaration sweep on it - the lever, if
it exists, has to change which value mwcc considers longer-lived.
