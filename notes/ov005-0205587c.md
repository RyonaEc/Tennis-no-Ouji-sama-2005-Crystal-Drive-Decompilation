## What it does

`base = *(u8 **)data_ov005_020c9740`, `rec = base + 0x460c`:

1. `*(u16 *)(base + 0x438e) = 0`
2. three-way initialiser on `a0` writing `rec[0x10..0x13]`:
   `1` -> 0x80,0x80,0x60,0x60; `7` -> 0x80,0x80,0,0xc0; else 0,0xff,0,0xc0
3. `for (i = 0; i < 2; i++)` copies the eight halfwords `rec[0x10..0x17]` into
   `tbl[k][i]` for k = 0..7, i.e. `rec + i*2 + k*4` - a `s16[8][2]` transpose.
   The k loop is written out (eight statements); retail keeps the `&tbl[0][i]`
   pointer in `r5` and uses `#4`/`#8`/`#0xc` displacements, which is exactly what
   `s16 (*tbl)[2]` produces.
4. `idx = *(u16 *)(base + 0x438e)`, `p = rec + idx`, then
   `0x04000040 = ((rec[idx] << 8) & 0xff00) | (p[2] & 0xff)` and
   `0x04000044 = ((p[4] << 8) & 0xff00) | (p[6] & 0xff)`. The first operand is
   addressed as `rec[idx]` (separate scale) and the rest through `p` - both forms
   are present in retail, so both belong in the source.

`build/cand/o5_587c_b.c` is that transcription: **336 B, every instruction in
retail's order**, with the transpose, the `s16` loads/stores and the pack masks
all matching.
